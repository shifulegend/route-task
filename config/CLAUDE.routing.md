## Model routing (always on. Goal: the same result for the fewest Claude tokens; free models count as 0)
- Split the task into parts and tag each silently: private? / D = who / R = where. Take the cheapest rung that works. Write the tags only in a plan the owner will read.
- **Private first** (bank, tax, ERP, ITR, personal mail, vault, credentials): stays on this machine, Anthropic models only, or no AI; never `cheap-llm`, `agy-ask`, CI, cloud, Colab or a team. Private plus heavy: split it; only a part holding no private data may go out, tested with made-up data, and its plan line says "made-up data". Cannot be split: all of it stays here.
- **D, who:** D0 script or tool, no AI: count, search (grep), reshape, convert, run tests > D1 free model for one-shot non-private text (label, classify, summarise, extract, draft): `node ~/.claude/bin/cheap-llm.mjs --system "<output format, no explanation>" < in.txt > <final file> && <check>`, run in the foreground with the Bash tool's `timeout` set to 310000 ms (never left to go to the background), the whole list in ONE call, straight into the final file, check in the same command; one line of text per item out of code or files (docstrings): script extracts, free model writes, script inserts, then `python3 ~/.claude/bin/draft-check.py <key<TAB>text file> --expect N` (exit 1: redo the batch one rung up; exit 0: skim only the 3 lines it prints), no helper; exit 3: use `haiku-helper` (if the message says "no backend configured", offer the owner once: OmniRoute or a provider API key, see skill `route-task` reference/cheap-models.md; never invent keys); exit 4 (looks private) is final. Stronger: `agy-ask` (Google Antigravity, non-private only, max 30/day) > D2 `haiku-helper`: mechanical work that needs files or tools, checkable > D3 `sonnet-helper`: multi-file edits or review checkable by tests, only if I am a higher tier than Sonnet or the job is many turns in an already long session > D4 me: design, root cause, security, irreversible actions, the final answer to the owner, anything costly to verify or to fix.
- **Size gate:** measure first (`wc -c`; never Read a big file whole, use grep or head). If more than about 20 KB would enter my context, or I would write more than about 4 KB, hand it to D0-D2 by file path and take back a file plus at most 10 summary lines. Below the gate I do it myself: a script is fine, a helper or free model is not.
- **Few turns:** one script or one batch of parallel tool calls, not many small steps. Check results with a tool (count, grep, tests, schema, diff), never by re-reading and never with a second model; sample at most 3 items; a failed sample or a helper's own doubt fails the whole batch, never patch single items; on failure retry once one rung up, then do it myself.
- **R, where** (highest that fits): R0 here if it fits > R1 GitHub CI: plain build or test of a repo, never a benchmark > R2 cloud session (runs up to about an hour): over 1.9 GB RAM, over 10 minutes, big downloads, many cores, benchmarks or anything timed, screenshots > R3 Colab, not a cloud session: a GPU, or any run of several hours, or tens of GB of disk (up to about 100 GB). Heavy work never runs on this server. Code edits are routed by D even when the run goes out.
- First use, or any "not found" / "no backend configured" error: run `sh ~/.claude/bin/route-doctor.sh` and help the owner fix what it lists (skill `route-task`, section 0a).
- Load skill `route-task` only before: a remote session, Colab, an agent team (parallel workers that must cross-check each other), a private-plus-outside mix, a permission-mode problem, or a case these lines do not settle. Not for light work.
- Use "ultrathink" only for root-cause debugging after a failed attempt, architecture, security review or ambiguous multi-constraint decisions; never for routine work.
- Antigravity only through the official `agy` CLI via `agy-ask`; the old proxy/adapter are uninstalled and the first account is banned, so never reinstall or use them.

## Remote sessions (enforced; full rules in skill `route-task`, section "Remote-session protocol")
- Before `create_session` or any remote/long-running work: read that section. A PreToolUse hook (`~/.claude/bin/rs-guard.py`) blocks `create_session` unless: title `RS/<area>/<task>/<date>`, a cloud `environment_id` (FulllAccess/Default; the default bridge env is this machine), tag `rs-managed`, `permission_mode: auto`, prompt with a deadline and hard stop, at most 4 running (ledger `~/.claude/state/rs-ledger.md`). Run `get_session` (no argument) first; if mode is `plan`, ask the owner to re-select Auto in the app.
- Log every child in the ledger; archive only after the result is saved and verified; sweep `rs-managed` sessions at start and end of work.
- Watch children: if a reply is overdue, read `get_session` and then the child's transcript newest-first (small `list_events` pages), update the ledger and the skill's Lessons log yourself.
