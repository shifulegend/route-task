## Skill design rules (official Anthropic guidance, checked 2026-11-13)
Sources: platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices, code.claude.com/docs/en/skills, anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills.
- Only name and description load at startup; SKILL.md loads when the skill is used and then stays in context every turn ("every line is a recurring token cost"); reference files cost nothing until read; scripts are executed, not loaded.
- SKILL.md under 500 lines; after compaction the first 5,000 tokens of each skill are kept (25,000 shared), so key instructions go at the top.
- Reference files one level deep from SKILL.md, descriptive names, a contents line when over 100 lines.
- Description: third person, what it does plus when to use it, key use first; 1,024 characters (listing cuts at 1,536).
- Only add what Claude does not already know; one term per idea; one default, not a menu; no time-sensitive text in the rules (dated facts go in this file).
- Test with a fresh session and at least three scenarios after any large edit.
- 2026-11-13: v2 A/B (14 tasks x2 arms, results-2026-11-13-v2): skill loads in 14/18 medium+large tasks and hands labelling to the free model, but Claude cost above the empty task was HIGHER with the skill (medium -37%, large -21%) because loading it adds turns and ~2.4k tokens; tasks of 12-37 KB are too small to repay that. Fix the load cost before expecting savings.
- 2026-11-13: second A/B test (56 scenarios) showed no saving. Cause: loading this skill costs about $0.02 per session, more than a light task can save, and the skill-less model was already frugal. Fix: the rules that decide a route moved into the always-on "Model routing" lines of `~/.claude/CLAUDE.md`; SKILL.md keeps procedures only and its description no longer triggers on light work; light-routing detail moved to reference/handover.md. Size gate raised from 12 KB read / 2.5 KB written to 20 KB / 4 KB. Old rule "Needs an agent AND a GPU: the agent runs in a cloud child (R2), the compute in Colab (R3)" replaced: code edits are routed by D, only the GPU run goes to Colab. `cheap-llm` now picks the long chain by itself above 12 KB input.
- 2026-11-13: test-harness lesson: work folders under `~/.claude` let skill-less test arms find the skill through the parent folder. Test work folders live in the temp folder; a run records `skill_listed`.
- 2026-11-14 Test v3 (72 runs): light tasks save only on bulk text that needs understanding (about 60% on 200-600 semantic labels); keyword labelling, filterable documents and counting show no gain because plain Claude already scripts them. Always-on lines cost about one cent per session.
- 2026-11-14 Haiku helper wrote 208 docstrings from 3-line previews: 125 right, and it said "approximate". I patched one sampled item and accepted. Rule: a failed sample or a helper's own doubt fails the whole batch. Route for one line per item: script + `cheap-llm` in one call + script (200 of 208 right).
- 2026-11-14 Free-model hand-overs wasted 2-3 turns on a scratch file, a move and a separate check. Rule: output straight into the final file, check in the same command.
- 2026-11-14 Plans sent 90 GB / 8 hours to a cloud session and did not form a team for reviewers who cross-check. Added "highest that fits" and a few words on what a team is to the always-on lines. Not yet re-tested (weekly usage limit reached during the test: check the allowance before a long test).
- 2026-11-14 New route tried by hand on the 60-file fixture (script extracts 208 function bodies, 33 KB -> one `cheap-llm` call -> script inserts): 208 of 208 right, files otherwise unchanged, no Claude model in the pipeline. Full bodies, not previews, are what made the difference.

Gemini free tier answered 429 after several 30-80 KB calls within minutes: the fall-back to `haiku-helper` worked and still saved. Space big free-model calls out.
